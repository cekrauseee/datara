A API lê PostgreSQL; visitas não baixam arquivos do TSE. A CLI importa o primeiro turno oficial de 2026, descobre códigos de pesquisa/eleição/cargo pelo EA11, lê catálogos EA12, agregados oficiais EA20, seções principais/agregadas EA16 e BU totalizado do EA18. Inclui presidente, governador, senador, deputados federais/estaduais/distritais, conselho distrital de Fernando de Noronha e resultados presidenciais do exterior quando aplicáveis.

## Setup local integrado

Na raiz:

```sh
pnpm install --frozen-lockfile
pnpm run setup
pnpm dev
# Ctrl+C encerra a sessão.
pnpm dev:stop
```

Use sempre `pnpm run setup`: `pnpm setup` é comando interno do pnpm. PostgreSQL 18 deve estar instalado. O script procura Homebrew `postgresql@18`, `PG_BIN` explícito ou ferramentas compatíveis no PATH. Não instala pacotes do sistema nem serviço de login.

Sem conexão fornecida, setup inicializa `.data/postgres`, ligado só a `127.0.0.1:55431`, e cria `datara` com autenticação trust local de desenvolvimento. Um marcador de propriedade impede assumir/resetar um diretório inicializado manualmente. `apps/api/.env` armazena conexão e caminhos absolutos de arquivo/fotos, preservando valores/comentários. Fontes ficam em `.data/elections` e fotos em `.data/public/photos`. Ao parar, banco, fontes, fotos e configuração permanecem; faça backup juntos.

Setup aplica migrações e importa AC/DF/PE/ZZ apenas se não houver publicação. Reaproveita publicações existentes, inclusive nacionais. Um UUID inicial é checkpointado em `.data/local-setup.json`; repetir retoma import interrompido, sem aquisição nacional automática. Duas fotos presidenciais são preparadas uma vez por publicação ativa. `pnpm run setup --offline` funciona com arquivo completo de piloto/fotos existente.

`pnpm dev` não reimporta. Lê configuração salva, reinicia apenas banco gerenciado/marcado, verifica portas e executa web/API. API padrão 3000 e Vite fixo 5173. Se ocupadas, pare o serviço conflitante ou mude `PORT`; processos não relacionados não são encerrados. `pnpm dev:stop` para só o cluster marcado e preserva seus dados. Bancos externos não são iniciados/parados.

Para banco de desenvolvimento existente, forneça `DATABASE_URL` em `apps/api/.env` ou no ambiente do primeiro setup. Setup migra/popula esse banco escolhido. Recusa URLs não loopback/host overrides sem `--allow-external-database`; a opção só se aplica a um alvo de desenvolvimento explicitamente escolhido e não provisiona serviços. Conflito entre shell e `.env` falha em vez de mudar alvo silenciosamente. O `.env` é privado/ignorado; credenciais não são impressas.

Configuração nova usa `.env.example`, preservando comentários, ordem e opções. Repetições preservam configuração e acrescentam apenas valores ausentes. Ao migrar do antigo `.env` da raiz, mova-o para `apps/api/.env` antes do setup. Runtime/migração/ingestão/fotos também leem esse arquivo nativamente; shell pode sobrescrever para usos avançados. Comandos manuais abaixo são alternativas.

## Banco local

Use PostgreSQL 18 existente com `DATABASE_URL` ou Compose opcional; o projeto não instala Docker:

```sh
export POSTGRES_PASSWORD='choose-a-local-password'
docker compose up -d postgres
export DATABASE_URL='postgresql://datara:your-local-password@127.0.0.1:5432/datara'
pnpm --filter @datara/api db:migrate
```

Compose liga localhost e preserva PostgreSQL em volume nomeado. `docker compose stop` para sem apagar volume. Não remova o volume sem intenção de descartar dados. `.env.example` documenta as opções; shell tem prioridade sobre `.env`.

Setup nativo macOS com armazenamento persistente e sem serviço de login:

```sh
HOMEBREW_NO_AUTO_UPDATE=1 brew install postgresql@18
export PG_BIN="$(brew --prefix postgresql@18)/bin"
mkdir -p "$PWD/.data"
# Cria cluster novo; nunca use diretório com dados existentes.
# -W pede uma senha local.
"$PG_BIN/initdb" -D "$PWD/.data/postgres" -A scram-sha-256 -W --encoding=UTF8
"$PG_BIN/pg_ctl" -D "$PWD/.data/postgres" -l "$PWD/.data/postgres.log" -o '-h 127.0.0.1 -p 5432' start
"$PG_BIN/createdb" -h 127.0.0.1 -p 5432 -U "$(whoami)" datara
export DATABASE_URL='postgresql://YOUR_USER:YOUR_PASSWORD@127.0.0.1:5432/datara'
pnpm --filter @datara/api db:migrate
# Preserva .data/postgres:
"$PG_BIN/pg_ctl" -D "$PWD/.data/postgres" stop
```

Use o papel criado pelo `initdb` (usuário do sistema por padrão). Codifique caracteres especiais da senha na URL. Se 5432 estiver ocupada, escolha outra porta em todos os comandos/conexão. Reiniciar o mesmo cluster exige só `pg_ctl start`, não `initdb`.

Para verificação isolada descartável:

```sh
# Pré-requisito macOS somente se ainda não instalado:
HOMEBREW_NO_AUTO_UPDATE=1 brew install postgresql@18
export PATH="/opt/homebrew/opt/postgresql@18/bin:$PATH"
initdb -D /tmp/datara-postgres-test -A trust --no-locale
pg_ctl -D /tmp/datara-postgres-test -l /tmp/datara-postgres-test.log -o '-h 127.0.0.1 -p 55432' start
createdb -h 127.0.0.1 -p 55432 datara_test
export DATABASE_URL="postgresql://$(whoami)@127.0.0.1:55432/datara_test"
# Pare ao concluir:
pg_ctl -D /tmp/datara-postgres-test stop
```

Esses comandos usam trust local e ligam só localhost. Para banco durável, use diretório separado e autenticação apropriada. Nunca sobrescreva cluster existente.

## Popular e retomar

O arquivo de fontes é persistente, ignorado pelo Git, e deve ser preservado junto ao banco. `--archive` resolve relativo ao pacote API sob filtro pnpm; forneça caminho absoluto:

```sh
export ELECTION_ARCHIVE_DIR="$PWD/.data/elections"
# Catálogos/agregados por disputa são nacionais; observações municipais/zonais
# e até dois BUs principais por UF ficam limitados a AC/DF/PE/ZZ.
# A seleção inclui Noronha e prioriza principais com seções agregadas.
pnpm --filter @datara/api elections --scope pilot --archive "$ELECTION_ARCHIVE_DIR" --pilot-ufs ac,df,pe,zz --municipalities 1 --sections 2

# Estimativa nacional: baixa só os catálogos EA11/EA12/EA16, monta o inventário, projeta
# requisições, disco, banco e horas, e deixa a publicação pausada:
pnpm --filter @datara/api elections --scope national --archive "$ELECTION_ARCHIVE_DIR" --estimate

# Aquisição nacional completa, com todas as unidades aplicáveis, retomando a publicação
# estimada (padrões de rede explícitos):
pnpm --filter @datara/api elections --scope national --archive "$ELECTION_ARCHIVE_DIR" --resume PUBLICATION_UUID --concurrency 6 --rate 20 --timeout 60 --progress-interval 30

# Retome com o MESMO UUID, escopo, limites e arquivo:
pnpm --filter @datara/api elections --scope pilot --resume PUBLICATION_UUID --archive "$ELECTION_ARCHIVE_DIR" --pilot-ufs ac,df,pe,zz --municipalities 1 --sections 2

# Nova publicação a partir do arquivo local, sem rede:
pnpm --filter @datara/api elections --scope pilot --offline --archive "$ELECTION_ARCHIVE_DIR" --pilot-ufs ac,df,pe,zz --municipalities 1 --sections 2

# Versões novas das fontes em nova publicação:
pnpm --filter @datara/api elections --scope pilot --refresh --archive "$ELECTION_ARCHIVE_DIR"

# Preparar sem tornar ativo, depois publicar explicitamente:
pnpm --filter @datara/api elections --scope pilot --no-publish --archive "$ELECTION_ARCHIVE_DIR"
pnpm --filter @datara/api elections --publish PUBLICATION_UUID
```

A CLI imprime UUID imediatamente. `--stop-after N` pausa após N unidades para verificar interrupção. O piloto marca `scope=pilot, complete=false`; votos de seções ausentes nunca são zeros nacionais. Tem catálogos de disputas aplicáveis, mas só observações/BUs escolhidos. Áreas só catalogadas podem não ter resultado. Limites de piloto não limitam `--scope national`.

Aquisição nacional é comando separado; a seção Aquisição nacional abaixo descreve política de rede, progresso e estimativa. O arquivo por hash deduplica bytes; cache de URLs permite reutilização. `--refresh` substitui esse cache apenas para novas aquisições; retomadas usam manifesto congelado. `--offline` falha se fonte exigida estiver ausente/corrompida. Preserve banco e arquivo para procedência/replay.

## Aquisição nacional

O primeiro turno nacional tem 58.896 unidades EA20 e 499.248 seções principais; todas menos 41 têm arquivo auxiliar, quase sempre com BU: cerca de 1,06 milhão de requisições. Rode `--estimate` antes. Ele baixa só os catálogos, conta unidades por tipo e projeta requisições, disco, banco, linhas e horas a partir dos EA20 de disputa arquivados e de constantes medidas no piloto. Declara que nenhum arquivo de resultado foi baixado e deixa a publicação pausada para a carga completa retomá-la.

Todas as requisições ao TSE de uma execução passam por um único fetcher: `--concurrency` requisições simultâneas (padrão 6), `--rate` inícios por segundo no processo inteiro (padrão 20, no máximo o limite do TSE de 100 por IP) e `--timeout` por tentativa em segundos (padrão 60), cobrindo cabeçalhos e corpo. Erros de rede, timeouts, HTTP 408 e 5xx são repetidos até seis tentativas, com backoff exponencial de 1 s a 32 s, jitter de ±25% e `Retry-After`. HTTP 429 ou 403 indica bloqueio do IP: todas as requisições aguardam cool-down de 10 min 30 s, pois insistir durante o bloqueio o renova. HTTP 404/410 nunca é repetido nem vira ausência: a execução pausa com a URL em `import_runs.error`, e três ausências seguidas interrompem todas as requisições. Corpos acima de 64 MiB são rejeitados; o `User-Agent` identifica o projeto.

A vazão é o menor entre `--rate` e o limite imposto pela latência. Com latências do TSE de 0,31–0,55 s medidas em conexões já abertas, cada requisição simultânea completa cerca de 2,4 por segundo, e os padrões sustentam cerca de 15 por segundo; usar a taxa inteira exige `--concurrency 10 --rate 20`, ou `--concurrency 18 --rate 40`. Essas opções são operacionais: não ficam gravadas na publicação e podem mudar entre retomadas.

As unidades pendentes são listadas uma vez por execução na ordem semântica: todo EA20 antes dos arquivos de seção, disputas completas antes de observações locais. Uma janela de 4 × concorrência unidades à frente é baixada só para o arquivo, bytes completos em `sha256/` e depois a referência da URL, incluindo o BU escolhido pelo auxiliar de cada seção. A normalização continua sequencial: normalização, estado e contador de cada unidade comitam numa transação, lendo os bytes pré-baixados pelo mesmo manifesto e verificação de hash. Uma escrita interrompida à força deixa no máximo arquivo temporário, removido numa partida seguinte quando tiver mais de cinco minutos. Com `--refresh`, fonte adquirida pela própria execução não é baixada de novo.

A cada `--progress-interval` segundos (padrão 30) a CLI imprime uma linha JSON com unidades feitas na execução e na publicação, unidades e requisições por segundo numa janela de cinco minutos, bytes, retries, cool-downs e ETA; `import_runs` pode ser consultada durante a carga. SIGINT ou SIGTERM termina a unidade em gravação, aborta downloads, marca a execução como pausada e sai com 130 ou 143; um segundo sinal sai na hora. Retome com `--resume` e o mesmo escopo, limites e arquivo.

Com `--keep-going`, padrão de `--scope national` (`--no-keep-going` desliga), uma unidade que falha em validação ou decodificação é registrada e a execução segue; termina pausada listando as falhas e para em 50. Unidades falhas continuam pendentes, sem reduzir cobertura. Falhas de EA20 pausam antes de qualquer BU de seção, que resolve números de urna contra candidaturas do EA20. A fonte de uma unidade falha fica congelada no manifesto: retomar repete os mesmos bytes, e fonte corrigida exige nova publicação com `--refresh`. Falhas de aquisição pausam a execução em vez de virar falha de unidade.

A situação EA18 de cada seção principal decide o BU. `Totalizada` usa o arquivo `bu` ou `busa` do único hash `Totalizado`. `Não instalada`, `Não apurada`, `Anulada` e `Recebida` (recebida, não totalizada) não têm BU totalizado: a unidade termina como `official_absence` e a situação fica nos metadados do manifesto. Outras situações de seção ou hash, mais de um hash totalizado ou seção totalizada sem BU falham. O TSE não gera auxiliar para seção sem arquivos de urna, e o EA16 omite seu `da`/`ha`; essas seções viram ausência oficial sem requisitar o arquivo inexistente, e a validação exige que `sni` mais `sna` (seções não instaladas ou não apuradas) do EA20 de cada zona as expliquem. No país são as 41 seções do exterior informadas como não instaladas.

A reconciliação compara cédulas totais em toda zona cujas seções principais têm BU ou situação oficial sem BU; ausências não contribuem cédulas impressas. `coverage` também informa `officialSectionStatuses` (seções por situação EA18), `sectionsWithoutAuxiliaryFile` e `unreconciledZoneResults` (resultados de zona fora dessa comparação).

Estimativa medida em 2026-10-08 com o arquivo do piloto: cerca de 10,3 GB de fontes (cerca de 19 GB alocados com blocos de 4 KiB e referências de URL); 175–315 milhões de linhas e 57–102 GB de PostgreSQL com índices; cerca de 20 horas de download com os padrões, 14,7 a 20 requisições por segundo efetivas e 7,3 a 40; 1,4–1,9 hora de normalização, sobreposta aos downloads. As faixas vêm das linhas por BU, 322 em média nas seções domésticas do piloto e até 600 supostas para seções urbanas grandes.

## Publicação e integridade

Migração `001-election` aplica uma vez com transação/advisory lock. Cada import tem UUID/publicação em preparação. PostgreSQL guarda manifesto, tarefas esperadas, conclusão, catálogos e observações normalizadas. Normalização e marcador de conclusão de cada unidade commitam juntos; retry substitui unidade, sem somar deltas. Bytes brutos são gravados atomicamente por SHA-256 antes da linha de manifesto. Bytes corruptos falham verificação.

Publicações são imutáveis pelo importador. Imports novos preservam anteriores. Validação exige todas as unidades esperadas, observações EA20/BU e nenhuma diferença inexplicada de cédulas em zonas completas. Publicação e ponteiro ativo mudam na mesma transação. Falhas/pausas não mudam dataset ativo. Seção sem BU totalizado exige situação EA18 oficial, ou entrada EA16 sem auxiliar explicada pelos totais de seções do EA20 da zona; arquivos ausentes, estados desconhecidos e hashes ambíguos falham em vez de virar zero.

Seções agregadas preservam IDs e `principal_area_id`, sem resultado duplicado. Zonas são fatias municipais; consumidores de zona completa precisam combiná-las. IDs são códigos eleitorais com correspondência opcional ao mapa; exterior não tem geometria. Chaves estrangeiras compostas impedem ligações entre publicações/disputas diferentes.

EA20 preserva grupos brutos em metadados e colunas numéricas explícitas. `vap`, destino e `pvapn` oficial permanecem. Votos nominais/legenda computados e válidos são separados. Votos válidos EA20 e votos impressos BU são medidas diferentes: `valid_votes` no BU é null, e Senado pode ter cédulas impressas em dobro do comparecimento. Votáveis sem candidatura verificada ficam em `votable_results`, sem candidaturas inventadas. Linhas ausentes são desconhecidas salvo garantia de zero pelo contrato. Não materializa produto cartesiano candidatura/seção.

O leitor BU2026 usa ASN.1 oficial de setembro de 2026, valida identidade pelo inventário e rejeita estruturas não suportadas/criptografadas. Não autentica assinatura. Bytes originais/SHA-256 preservam evidência; hash não verifica assinatura TSE. O fluxo nacional não foi executado no desenvolvimento; variantes além do piloto seguem validação que falha em caso de dúvida.

## Verificação

```sh
pnpm --filter @datara/api check:bu
pnpm --filter @datara/api check:acquisition
pnpm --filter @datara/api check:settings
pnpm --filter @datara/api typecheck
pnpm --filter @datara/api lint
pnpm --filter @datara/api build
```

`check:acquisition` exercita o fetcher e a pré-busca do arquivo contra um servidor roteirizado, sem rede nem banco: teto de taxa, concorrência limitada, backoff e `Retry-After`, cool-down de 429/403, 404 sem retry e parada após três, timeouts, limite de tamanho, abortos sem arquivo temporário e remoção de temporários antigos.

Fixtures oficiais versionadas de Porto Walter, Abu Dhabi SA e Noronha cobrem presidente, legenda proporcional, duas escolhas do Senado, campos opcionais, cargo 25, participação por eleição e rejeição de truncamento. Foram decodificadas independentemente com `asn1tools`/ASN.1 preservado. Checks de banco/API estão em [desenvolvimento](/development/setup).

Integração de ingestão exige arquivo padrão completo do piloto e banco PostgreSQL isolado explícito. Cria/remove schema temporário, importa documentos reais offline, verifica interrupção/repetição, retenção de publicação e integridade composta. Também adquire o piloto de um TSE roteirizado servido pelo arquivo para um diretório temporário, com pré-busca em concorrência 4, pausa por 404, interrupção e retomada cujas tabelas igualam a importação offline, e cobre situações EA18 sintéticas, seções sem auxiliar, ausências oficiais na reconciliação, estimativa, opções de retomada antigas, `--keep-going` com retenção por falha de EA20 e parada no meio da fila. Redução sintética de um voto ocorre em transação revertida só para testar substituição; nunca é publicada como dado oficial.

```sh
createdb -h 127.0.0.1 -p 55432 datara_ingestion_check
export TEST_DATABASE_URL="postgresql://$(whoami)@127.0.0.1:55432/datara_ingestion_check"
export ELECTION_ARCHIVE_DIR="$PWD/.data/elections"
pnpm --filter @datara/api check:ingestion
# Cleanup do schema é automático:
dropdb -h 127.0.0.1 -p 55432 datara_ingestion_check
```

## Fotos oficiais e apresentação

Fotos são aquisição opcional separada. A CLI lê diretório EA11 `ft` congelado da publicação e IDs de candidaturas, baixa `<sqcand>.jpeg` e grava JPEGs nomeados pelo SHA-256 do ID público completo. Inicialização da API descobre esses arquivos e prioriza override manual disponível, foto oficial e `null`. Reinicie após mudanças.

```sh
export ELECTION_ARCHIVE_DIR="$PWD/.data/elections"
export PHOTO_DIRECTORY="$PWD/.data/presentation" # contém photos/; use o mesmo no servidor
# Piloto real rápido: presidente e deputado federal do Acre.
pnpm --filter @datara/api elections:photos --contest BR-2026-1:6257:1:br --limit 1
pnpm --filter @datara/api elections:photos --contest BR-2026-1:6259:6:ac --limit 1
# Todas as candidaturas principais da publicação ativa (nacional quando ela for nacional):
pnpm --filter @datara/api elections:photos --concurrency 6 --rate 20
# Publicação específica, replay ou atualização:
pnpm --filter @datara/api elections:photos --publication PUBLICATION_UUID --offline
pnpm --filter @datara/api elections:photos --refresh
```

O output padrão é `apps/api/public/photos/`. Checkpoints de URL, SHA-256 originais e manifestos por publicação ficam no arquivo eleitoral ignorado, separados do manifesto imutável de votos. Registram URLs, coleta, HTTP e hashes. Fotos opcionais 404/410 não bloqueiam publicação; outras falhas saem com erro para retry. Downloads usam a política do fetcher de aquisição (concorrência, taxa, retry e cool-down), com timeout de 30 s e limite de 10 MiB, e imprimem progresso a cada `--progress-interval` segundos. Vinte e cinco fotos ausentes seguidas interrompem a execução, pois 404 repetidos podem bloquear o IP; repetir continua dos checkpoints de URL. SIGINT para de agendar fotos, mantém checkpoints concluídos e grava o manifesto. Replay offline exige todas as fontes solicitadas; use o mesmo contest/limite de um piloto parcial.

Arquivos gerados modificados manualmente e JSON de apresentação são preservados. Refresh só substitui gerado se o hash atual corresponder ao original adquirido. Faça backup do diretório de fotos também.

Para check focado de fotos/API, use banco com piloto publicado e as duas fontes acima:

```sh
export TEST_DATABASE_URL="$DATABASE_URL" # precisa ser dataset local de testes populado
pnpm --filter @datara/api check:photos
```

O check reprocessa JPEGs reais em diretório temporário, verifica `photoUrl`, bytes HTTP/hash, manifesto de votos inalterado e remove só seu output temporário. Também adquire um lote de um servidor roteirizado para arquivo temporário: concorrência limitada, retry, fotos ausentes e falhas, e nova execução que repete só a falha. `check:presentation` cobre precedência e ausência de imagem separadamente.
