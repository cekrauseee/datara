## Runtime boundaries

`apps/web/src/main.tsx` mounts React in Strict Mode and `app/app.tsx` renders `MapExplorer`. Vite uses the React Compiler, Tailwind CSS v4 and the `@/` source alias. UI primitives are local shadcn/Base UI components under `components/ui`; semantic CSS tokens and Geist typography are defined in `src/index.css`. Each visited country keeps its page mounted and hidden while inactive, preserving camera and search without rebuilding geometry.

The Hono API is independent of the geographic map: without a collection, `/br` and `/us` make no API request. Its election module reads PostgreSQL publications through validated OpenAPI routes, explicit parameterized queries, electoral metrics and local presentation resolution. Ingestion scripts own acquisition, normalization, migrations and atomic publication; request handlers never fetch TSE or read raw BUs. Responses are compressed, reads pinned to an explicit publication are cacheable for an hour, territory queries expand only the levels above the requested one through the `areas_parent` index, and distribution and map refuse scopes beyond their depth and area limits instead of scanning them. See [API contracts](/api/usage) and [ingestion](/development/ingestion). The web application uses no client-side router dependency, authentication or server-side rendering.

The documentation is a separate Next.js application: localized content and search indexes are prerendered during the build. Proxy negotiates `Accept-Language` only on unprefixed entry URLs; reading the documentation needs no API/database connection.

## Data flow

1. The URL identifies a country and optional area. Country changes retain already visited pages instead of recreating their Canvas.
2. The data hook requests country metadata through the cache and worker. The worker owns decoded coordinate arrays; React receives area metadata rather than full national geometry.
3. The worker projects a scene for the current viewport and sends serialized SVG paths and bounds. Six decimal places limit serialization rounding at high zoom.
4. The UI converts paths to `Path2D`, caching the latest viewport for each map. Rendering uses those prepared paths without reprojecting vertices on every frame.
5. US details are downloaded by state and projected on demand. Selecting a locality can request that one feature first, so camera movement need not await preparation of every local shape.
6. Canvas callbacks update selection, hover, readiness and completed zoom. Navigation writes the selection into the URL.

With the elections collection:

1. `useElection` reads the election parameters and resolves the session once: `/elections?country=BR&year=2026&round=1` gives the edition and the active publication, which then travels with every request as `publicationId`. If that publication disappears (404), the session is re-pinned once and the cache is cleared.
2. `/contests` loads once per session. The contest is derived from the office and the current electoral area, found by the mesh `featureId` (or by `area`, zone and section), choosing the scope that contains the area.
3. Each query is a slot keyed by its full URL. A new key discards the late response of the previous one; the in-memory cache shares promises and evicts failures, and "Tentar novamente" evicts the entry and repeats.
4. `useMapLayer` requests the contest's `/map` (or the office map in the national view), classifies the items into colour classes and hands the layer to the Canvas through `setLayer`. At municipal grain in the national view, the state map comes along for the tooltip.
5. The panel requests the area's `/results`, `/areas` for zones, sections and localities and, in focus, `/results` for the area, the level above and the contest scope, plus `/distribution` for the level below.

## Keeping interaction responsive

- **Worker isolation:** network response parsing, topology decoding, mesh construction and bulk projection do not block the UI thread. Paths cross the boundary instead of large nested coordinate arrays.
- **Shared frame budget:** `Path2D` creation shares a target budget of 3 ms per frame across concurrent preparation tasks. This is a scheduling target, not a hard maximum for a single path conversion.
- **Cancellation:** a newer viewport cancels obsolete scene preparation. Worker projection loops yield periodically to receive cancellation messages.
- **Memory reuse:** promises, metadata, decoded data and projected scenes are reused. The latest scene per country is cached; scene detail caches reuse paths by state. There is no application-managed localStorage, IndexedDB or persistent cache. Ordinary browser HTTP caching is separate.
- **Frame coalescing:** draw and hover work use `requestAnimationFrame`. Zoom avoids notifying React on every animation step. Progress is clamped to avoid a negative first frame when RAF timestamps precede animation creation.
- **Picking on demand:** bounds and `isPointInPath` checks run for pointer interaction, rather than rebuilding clickable-area lists every animation frame.
- **Stable geometry:** state outlines are unions of the same lower-level arcs. Opaque land fills remain stable during zoom; shared boundaries are stroked separately.
- **Merged data layer:** the data layer merges one `Path2D` per colour class and state, so a national frame with 5,571 painted municipalities makes a few hundred `fill()` calls rather than one per municipality. Groups are built within the same 3 ms frame budget and swapped at once; while a new map loads, the previous layer stays painted.
- **Bounded display work:** offscreen bounds are skipped where applicable; geographic labels are not painted; device pixel ratio is capped at 2.

Cached geometry and visited pages trade memory for fast returns. Local details accumulate for explored states during a session. The implementation does not promise constant memory regardless of exploration, or a fixed frame rate on every device.

## Ownership and cleanup

React owns product state; Canvas owns camera transforms and transient drawing state; the worker owns bulk geography. Canvas teardown cancels RAF work, disconnects the resize observer and removes handlers. Worker errors reject pending requests; failed cached work can retry. Vite hot replacement terminates the worker. The worker is otherwise shared for the page lifetime.

Deep-link initialization, reduced motion, retained-country navigation and resize are different paths and must stay distinct: initial selection should animate, while returning to the same country should not reset or refit its camera.

## Measuring changes

Use the reproducible browser scenarios in [development and verification](/development/setup), including cold and warm selections. Measure frame intervals and long tasks, not only time spent calling Canvas methods: rasterization may be deferred, and decoding can dominate before drawing begins.

Keep viewport, pixel ratio, CPU settings and cold/warm state identical when comparing. Record measurements with those conditions; results from another machine are not a performance baseline for the current checkout.
