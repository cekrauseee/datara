---
title: Interpret results and coverage
description: Source bases, missing values, ties, aggregated sections and exterior.
---

Counts are integers; unavailable measures are `null`, never invented zeros. Percentages include numerator, denominator, basis and state; denominator zero is `undefined`. Candidate omissions remain unknown unless the stored complete-result contract explicitly guarantees zero.

`recordedCandidateVotesSum` sums all stored candidate rows for the result before pagination and includes their recorded destinations; it is not a valid-vote share. `printedNominalVotes` includes all nominal BU votables, including those without a verified candidacy. Judicial valid votes remain unavailable in a BU. Official EA20 `pvapn` is returned separately with its original competing-candidate basis.

Totals follow their source. In a BU, `nominalVotes`, `blankVotes`, `nullVotes` and `legendVotes` are the printed nominal, blank, null and legend vote types, and `noCandidateVotes` counts type 5 (office without a candidate); the five types add up to `totalVotes`. In EA20, `nullVotes` is the official `tvn`, which adds null (`vn`) and technical null (`vnt`) votes, and the total `tv` also adds valid, blank, annulled (`van`) and sub judice annulled (`vansj`) votes; those judicial categories do not exist in a BU, and `noCandidateVotes` is `null` for EA20, region sums and bulletins normalized before the field existed. BU and EA20 null votes are therefore different measures.

BU and judicial-totalization votes are not interchangeable: territorial contribution is unavailable when the selected scope and local result have different source bases. Turnout always uses that contest/result's own electorate, including Senate and Noronha distinctions.

Tied leaders remain an array. Senate's two-seat cutoff also exposes second-versus-third margin. In a BU, a nominal votable without a verified candidacy (a number outside the catalog or shared by several candidacies) is listed in `unresolvedVotables` and treated as a possible competitor holding exactly its own votes. The summary hides only what it could change: with `u` the largest such votable, `leaders` and `tie` are reported when `u` is below the first candidacy's votes (otherwise `leaders` is empty and `tie` false), `margin` when `u` is below the second's, and the Senate `seatCutoffMargin` when `u` is below the third's. Beyond those limits the value has null `votes` and `percentagePoints` and basis `unresolvedPrintedCandidateVotes`. Ties count each candidacy, so a tie for the lead keeps margin 0. No margin predicts election, and a local leader does not imply an elected candidate. `officialSelectedFlag` retains the source `e=s` indicator, which can include second-round selection; the complete official status and its scope accompany it. Proportional seat allocation is never inferred from candidate rank.

On maps, each item's `margin` is the difference between the two highest candidate counts in percentage points over the area's `shareBasis` (`printedNominalVotes` in a BU, `recordedCandidateVotesSum` in EA20), equal to the `metric=margin` value; a tie gives 0, and a missing result or second candidacy gives `null`. Maps use only states and municipalities, which come from EA20.

A result's `officialStatus` is a documented value, with a Portuguese `officialStatusLabel` and `officialStatusCode`, the stored code (provenance only). In EA20 the code is the TSE `and` field: `notStarted` (Totalização não iniciada, `n`, inferred from the specification), `inProgress` (Totalização em andamento, `p`) and `finished` (Totalização finalizada, `f`). A BU gives `printed` (Boletim de urna impresso), and a region sum `regionComplete` (Soma das UFs completa) or `regionPartial` (Soma das UFs parcial). Any other code yields `unknown` (Situação oficial desconhecida), never an error. `complete` reproduces the TSE final totalization flag (`tf`) in EA20. The exact meaning of `tf` could not be verified in the sources, and some results have `and=f` and `tf=n` with every section counted, so `complete` does not mean "every section counted". A candidacy's status (`Eleito`, `Suplente`, `2º turno`…) is the TSE's Portuguese text.

Candidacies carry `coalition` (`number`, `name`, `composition` and `type`: `party` for a party running alone, `coalition`, `federation` or `unknown`), `federation` (`number`, `name`, `abbreviation`, `composition` and `partyNumbers`, or `null`) and `runningMates` (`name`, `displayName`, `partyAbbreviation`, `officialId` and `role`: `vice`, `firstSubstitute`, `secondSubstitute` or `unknown`). Fields missing at the source arrive as empty text, empty lists or `unknown`; candidacies without a party (Fernando de Noronha's district council) have null `coalition` and `federation`.

Aggregated-section result requests return `state=shared`, `resultAreaId` of the principal and the shared totals. Distribution reports no isolated votes for those sections. Regions sum disjoint domestic UF EA20 observations, retain source references and report whether every member state was covered; exterior is separate. A known catalog area without an observation returns `state=unavailable`. Regions have Portuguese names (Norte, Nordeste, Sudeste, Sul, Centro-Oeste); IDs such as `region:north` do not change, and publications imported before that change keep their earlier names.

A publication reports its coverage in `coverage`, present in `/elections` and in every list: `scope` (`pilot` or `national`), `complete`, import units (`expected`, `completed`, `officialAbsences`), results (`results`, `buResults`, `buFiles`, `aggregates`), reconciliation (`reconciliation`, `reconciledZoneResults`, `unreconciledZoneResults`, `discrepancies`), official section statuses (`officialSectionStatuses`, `sectionsWithoutAuxiliaryFile`) and the pilot `selection` (`null` for a national publication). Keys an earlier publication did not record arrive as `null`. The official pilot is limited; a catalog area does not prove available votes.

Errors use `error.code`, `message`, `requestId` and optional field details. Invalid input is HTTP 400, missing resources/publications HTTP 404, database unavailability HTTP 503 and unexpected faults HTTP 500. A candidacy that does not exist in the publication is 404 `CANDIDATE_NOT_FOUND`; one from another contest is 400 `INCOMPATIBLE_CANDIDATE`. An office without a contest in the publication returns 404 `OFFICE_NOT_FOUND` on the office map. An edition without an active publication reads from `/elections/{electionId}` with `publication: null`, as in the list, while its data routes return 404 `PUBLICATION_NOT_FOUND`. In distribution, a `level` at or above the area's level is 400 `LEVEL_NOT_BELOW_SCOPE`. A query that exceeds the time limit is 503 `QUERY_TIMEOUT`, distinct from `DATABASE_UNAVAILABLE`: the database answers, but the requested slice is too large; narrow the area or the page. Query failures never become successful empty datasets. SQL and local paths do not appear in error responses; request IDs link internal diagnostics.
