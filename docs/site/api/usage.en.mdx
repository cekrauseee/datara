## Discovery

Run from the repository root. `pnpm run setup` saves `apps/api/.env`, prepares the database and imports the limited official pilot; `pnpm dev` starts web/API and restarts the project-managed database when needed. No repeated shell exports are required.

```sh
pnpm install --frozen-lockfile
pnpm run setup
pnpm dev
```

In another terminal (API defaults to port 3000; use the saved `apps/api/.env` `PORT` if customized):

```sh
curl -fsS 'http://localhost:3000/elections?country=BR&year=2026&round=1'
curl -fsS 'http://localhost:3000/elections/BR-2026-1/contests'
curl -fsS 'http://localhost:3000/elections/BR-2026-1/areas?level=municipality&uf=ac&limit=25'
curl -fsS 'http://localhost:3000/elections/BR-2026-1/areas?featureId=12'
curl -fsS 'http://localhost:3000/contests/BR-2026-1:6257:1:br/results?areaId=br&limit=25'
curl -fsS 'http://localhost:3000/contests/BR-2026-1:6259:5:ac/results?areaId=ac:01066:0004:0077'
curl -fsS 'http://localhost:3000/contests/BR-2026-1:6257:1:br/results?areaId=exterior'
curl -fsS 'http://localhost:3000/contests/BR-2026-1:6257:1:br/map?areaId=ac&metric=leader&level=municipality'
curl -fsS 'http://localhost:3000/elections/BR-2026-1/map?officeCode=3&level=municipality&metric=leader'
curl -fsS 'http://localhost:3000/openapi.json' > /tmp/datara-openapi.json
```

The documented schema is available at `/openapi.json`. Each of the ten routes has input/output schemas and stable errors. Root `/` still returns `{"message":"datara"}`. No route prefix or header versions the API.

See the generated [endpoint reference](/api/reference/elections) for parameters, response schemas and errors.

Use `publicationId` from the edition response in related queries to keep map and detail on the same snapshot. The server pins one published dataset inside a read-only repeatable-read transaction per request. Missing explicit publications fail with `PUBLICATION_NOT_FOUND`; they never silently switch. Successful (200) responses to queries with an explicit `publicationId` carry `Cache-Control: public, max-age=3600`: published data never changes, but editorial presentation fields (`color`, `photoUrl`, `displayName`) can change without a new publication, and those changes reach clients within an hour after the server loads them. Without the parameter no cache header is sent, because the active publication can change. Source IDs refer only to published datasets. Source responses omit archive paths and internal metadata. Source timestamps (`generatedAt`) are ISO-8601: TSE JSON files carry Brasília time with offset `-03:00` (assumption: TSE systems publish in that time, without daylight saving since 2019), and a BU carries the voting machine's local time without an offset, because the bulletin does not state the section's time zone. `/sources/{sourceId}` also keeps the original text in `generatedAtOriginal`; unrecognized text yields `null`. Bulletins imported before their emission time was recorded on the source have `generatedAt: null` in `/sources`.

Lists support `limit` (default 25, maximum 100) and `offset`, with deterministic ordering and total/hasMore, and carry the publication's `coverage`. `uf` and `country` ignore case (`uf=AC` equals `uf=ac`). Areas accept `featureId`, the map geometry identifier (IBGE state or municipality code). Candidate search accepts `q`, `partyNumber` and `officialId` (the TSE official `sqcand` identifier). Distribution requires `candidateId` and accepts `areaId`, `level` and `sort`; `level` must lie below the area's level in the order country, region, state, municipality, zone, section (otherwise 400 `LEVEL_NOT_BELOW_SCOPE`), and may be at most two levels below the area (`areaId` or the contest scope) in the sequence country, state, municipality, zone, section; regions only group states and count as the country. The default `level=municipality` therefore works for national contests, zones need a state or narrower area, and sections need a municipality or zone area. Deeper levels return 400 `LEVEL_TOO_DEEP`. `sort` orders the areas before paging: `area` (default) by ID; `votes`, `support` and `contribution` by that value, descending, with missing values last and the area ID breaking ties. `pagination.total` and each item's content do not depend on the order. For example, replace the IDs with values returned by the candidates endpoint:

```sh
curl -fsS 'http://localhost:3000/contests/BR-2026-1:6257:1:br/candidates?limit=1'
curl -fsS 'http://localhost:3000/contests/BR-2026-1:6257:1:br/candidates?officialId=OFFICIAL_ID'
curl -fsS --get 'http://localhost:3000/contests/BR-2026-1:6257:1:br/distribution' \
  --data-urlencode 'candidateId=CANDIDATE_ID' --data-urlencode 'areaId=ac' \
  --data-urlencode 'level=municipality' --data-urlencode 'sort=support' --data-urlencode 'limit=25'
```

Map metrics are `leader`, `margin` (percentage points between the two highest recorded candidate counts), `turnout` (percentage), `candidateVotes`, `candidateShare` and `contribution`. The last three require `candidateId`. Every item also carries `margin`, the same percentage-point margin as the `metric=margin` value (`null` without a result or a second candidacy), and the response carries `candidates`, a dictionary keyed by ID of the candidacies referenced in `leaders` and of the requested `candidateId`, with display name, number, color, photo, party and `contestId`. Maps permit only state or municipality levels and at most 10,000 areas; sections use paginated lists/distribution.

`GET /elections/{electionId}/map?officeCode=&level=&metric=` reads one office across all of its contests (for example governor in the 27 states), each within its own official scope, with `metric` `leader` (default), `margin` or `turnout` and `level` `state` or `municipality` (default). Each item names its `contestId`, `contests` lists the contests, `tseElectionId` is the TSE election code of those contests (equal to `contests[].electionId`, for example `6259`; not the edition ID in the path), and the 10,000-area limit applies to their sum. With `level=state`, each state contest returns its own state and the presidential contest returns the 27 states, with the exterior counted in `omittedWithoutGeometry`; municipal contests have no item at that level. An office without a contest in the publication returns 404 `OFFICE_NOT_FOUND`.

The API compresses JSON responses with gzip or deflate according to `Accept-Encoding` and sends `Vary: Accept-Encoding`. The official pilot municipality leader payload has 5,571 feature entries and measures 1,054,433 bytes uncompressed and about 45,200 bytes with gzip (`check:api`); this is a payload measurement, not a national-load latency guarantee. Exterior entries without geometry are counted separately.

Read [result interpretation](/api/interpretation) before comparing percentages or treating missing observations.
