## Descoberta

A API Hono lê dados publicados no PostgreSQL local. Importar `createApp` não inicia servidor, migrações nem downloads do TSE. O desenvolvimento usa `pnpm run setup` e `pnpm dev`; veja [ingestão](/development/ingestion). A porta padrão é 3000; use o `PORT` de `apps/api/.env` se alterado.

```sh
curl -fsS 'http://localhost:3000/elections?country=BR&year=2026&round=1'
curl -fsS 'http://localhost:3000/elections/BR-2026-1/contests'
curl -fsS 'http://localhost:3000/elections/BR-2026-1/areas?level=municipality&uf=ac&limit=25'
curl -fsS 'http://localhost:3000/contests/BR-2026-1:6257:1:br/results?areaId=br&limit=25'
curl -fsS 'http://localhost:3000/contests/BR-2026-1:6259:5:ac/results?areaId=ac:01066:0004:0077'
curl -fsS 'http://localhost:3000/contests/BR-2026-1:6257:1:br/results?areaId=exterior'
curl -fsS 'http://localhost:3000/contests/BR-2026-1:6257:1:br/map?areaId=ac&metric=leader&level=municipality'
curl -fsS 'http://localhost:3000/openapi.json' > /tmp/datara-openapi.json
```

O schema está em `/openapi.json`. As nove rotas têm validação de entrada e saída e erros estáveis. A raiz `/` retorna `{"message":"datara"}`. A API não é versionada por prefixo ou cabeçalho. Consulte [parâmetros, schemas e erros gerados](/api/reference/elections).

## Publicações e paginação

Envie `publicationId` da edição nas consultas relacionadas para manter mapa e detalhe na mesma publicação. Cada requisição usa uma transação somente de leitura e repeatable-read. Publicações explícitas inexistentes retornam `PUBLICATION_NOT_FOUND`, sem troca silenciosa. Respostas 200 de consultas com `publicationId` explícito trazem `Cache-Control: public, max-age=31536000, immutable`, pois uma publicação publicada não muda; sem o parâmetro não há cabeçalho de cache, porque a publicação ativa pode mudar. IDs de fontes referem-se apenas a dados publicados; respostas omitem caminhos de arquivo e metadados internos. Datas de origem mantêm o texto original quando o fuso não pode ser determinado.

As listas aceitam `limit` (padrão 25, máximo 100) e `offset`, com ordem determinística, total e `hasMore`. A busca de candidatos aceita `q` e `partyNumber`. Distribuição exige `candidateId` e aceita `areaId` e `level`; `level` fica no máximo dois níveis abaixo da área (`areaId` ou escopo da disputa) na sequência país, UF, município, zona e seção; regiões apenas agrupam UFs e contam como o país. Assim, o padrão `level=municipality` funciona em disputas nacionais, zonas exigem área de UF ou mais específica e seções exigem área de município ou zona. Níveis mais profundos retornam 400 `LEVEL_TOO_DEEP`. Substitua o ID de candidatura por um retornado pela API:

```sh
curl -fsS 'http://localhost:3000/contests/BR-2026-1:6257:1:br/candidates?limit=1'
curl -fsS --get 'http://localhost:3000/contests/BR-2026-1:6257:1:br/distribution' \
  --data-urlencode 'candidateId=CANDIDATE_ID' --data-urlencode 'areaId=ac' \
  --data-urlencode 'level=municipality' --data-urlencode 'limit=25'
```

## Métricas do mapa

As métricas são `leader`, `margin` (pontos percentuais entre as duas maiores contagens registradas), `turnout` (percentual), `candidateVotes`, `candidateShare` e `contribution`. As três últimas exigem `candidateId`. Mapas aceitam apenas UF ou município, com até 10.000 áreas; seções usam listas/distribuição paginadas. A API comprime respostas JSON com gzip ou deflate conforme `Accept-Encoding` e envia `Vary: Accept-Encoding`. O payload de líderes municipais do piloto oficial tem 5.571 entradas de features e mede 975.611 bytes sem compressão e cerca de 44.500 bytes com gzip (`check:api`). Essa medição não garante latência em carga nacional. Entradas do exterior sem geometria são contadas separadamente.

Leia [interpretação dos dados](/api/interpretation) antes de comparar percentuais ou tratar observações ausentes.
